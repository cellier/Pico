# Pico 与 Zoom Slides

本场会议准备可配对一个 Zoom Slides 文稿和完整讲稿。内容保存在本机准备中；开始语音代理后，讲稿、背景、材料及选择的记忆会按原有会议流程发送到百炼。

## 准备和使用

在 Pico 的“Background · 本场会议准备”中启用主动介绍，选择“导入演示脚本…”。脚本包含文稿链接、Zoom 中的完整标题、讲解语言、开场、每页分段台词及收尾。导入后可用“查看与编辑讲稿…”修改台词和等待回答的位置。仍可添加普通文档作为问答参考，也可改用原有提纲。

“检查 Slides 连接”只读当前 Zoom；“无声预演”在当前已打开的会议中开始共享并逐页确认，不调用模型，不开启音频。正常会议需按原有方式准备声音和本人接管。

自动共享从 Zoom 的 Files 近期列表选择唯一匹配的完整文稿标题，并在实际共享后核对文稿 ID、共享状态和页码。列表加载时允许短暂读回等待，不根据底部按钮单独推断文件身份。目前不自动搜索近期列表以外的旧文稿；准备时应先在 Zoom 打开指定文稿，并运行无声预演。目标缺失或同名不唯一会明确暂停，不会换用其他文件。

本地控制依靠正常授予 Telos 的辅助功能权限，不使用 Zoom 开发者账号、SDK 或远程控制服务。它绑定当前 Zoom 进程、会议窗口和文稿标识；遇到不同文稿、无法读回页码、权限不足、窗口变化或超时会停下并报告。

## 讲解流程

开场可以设置等待对方回答。共享确认成功后才开始第一页；每段以本机声音实际播放结束为准，再推进台词和页码。模型生成完毕不等于已经播完。

脚本中 `waitForReply: true` 的节点默认等待约 12 秒；计时从前一句声音实际播放结束开始。对方一直没有回答时，Pico 先说一句简短过渡，再从下一段尚未讲过的内容继续。每个节点可配置 `replyTimeoutSeconds`（1–120 秒），设为 `null` 表示一直等；省略时使用 12 秒，因此已有脚本不需要重新导入。`replyTimeoutTransition` 可设置该节点的过渡语；未填写时按脚本语言选择简短默认语句，中文为“那我先往下介绍，你随时可以打断我。”。该过渡也必须实际播放完成才能继续，不把下一段提前记为已讲。

听众发言、语音识别和回答处理期间，静默计时暂停；真实回答仍按原有问答流程衔接。轻微噪音被语音服务丢弃、没有产生文字或回答时，恢复原等待节点的计时。“我想问个问题”产生的等待没有超时；明确暂停、本人接管和会议收尾也不会被静默回退解除。

对方插话时立即清空待播声音。普通问题回答完再接回原段落；“可以问个问题吗”会等真正的问题；明确暂停会保持等待，直到要求继续。本人接管会同时停止声音和后续翻页。旧连接、旧语音及已取消操作的迟到回调不能推进讲稿。

收尾后进入自由交流，保留最后一页共享。`show_slide` 仅能切到本场已准备文稿的有效页码；回看不会重启介绍。停止预演、接管或结束讲解均不会自动关闭共享；用户可在 Zoom 中正常结束共享。

若听众明确要求提前收尾，应用会播放本场配置的结尾一次，保留当前页，不把跳过的内容记为已讲。明确开始另一场会议时会重新绑定 Zoom；暂停、续讲和当前会议重连不会变成新会话。

## 文件与验证

通用数据格式及纯流程在 `PicoPresentationScript.swift`，讲解协调在 `PicoScriptedPresentation.swift`，Zoom 控件适配在 `ZoomSlidesDriver.swift`。个人讲稿与会议准备仅保留在本机；`docs/meeting-packs/` 中的私人内容由 Git 忽略，不随仓库同步。

仓库提供可导入的[最小合成示例](examples/pico-presentation.example.json)，其中的文稿链接和标题均为占位数据。可先导入查看格式；连接或预演前，请替换为自己已在 Zoom 中打开的真实文稿链接、完整标题及对应页数和台词。

回归分别覆盖脚本游标、真实播放屏障、问答与打断、接管、共享读回、文稿/会议不符、隐藏编辑器页码、超时、取消，以及工具参数和迟到响应。2026-10-19 已在 Zoom 7.1.9（88375，英文界面）和安装版中通过一次完整无声预演：自动开始共享、逐页 1→6、保留第六页；用户确认观众端收到末页。同日受控双账号完整语音演练已验证自动共享、六页讲解、中文/英文切换、内容问答后续讲、精确收尾、自由交流回看第二页和按钮接管。实体全局快捷键未实测；段内恢复不是逐词续播。


## 会议收尾与离会

介绍结束仍保持最后一页共享，进入自由交流。`control_presentation(conclude)` 只收束介绍，不能退出 Zoom。

会前的“明确道别后自动离开 Zoom 会议”默认开启，可关闭。自动离会需要当前对方明确的结束或道别，以及模型的 `finish_meeting {}` 请求；材料、旧对话、介绍末页、静音、普通致谢都不构成离会指令。应用冻结讲稿，单独安排一句告别，只有该响应成功生成且音频实际播放清空后，才执行一次离会。接管、插话、重连、语音失败和等待超时会撤销本次离会。

结束请求必须对应同一句实时语音的有效转写；模型先给出工具请求时，应用会有界等待该句转写，不能借用之前的道别。告别采用独立的本机语音标记，普通回答不能代替告别推进离会。告别中又说“拜拜”会先停声；只有这句新道别和新的结束请求都确认后，才重新安排短告别。“先别走，我还有问题”会保留会议，不把任何打断自动解释为要求暂停。

自动收尾仅允许 Pico 自己离开。结束全场只能由本机用户选择“Zoom 会议收尾 → 结束所有人的 Zoom 会议（主持人）”，工具和参会者不能扩大范围。该菜单也支持 Pico 已停止时离开仍在进行的 Zoom。

原生退出驱动绑定当前 Zoom 进程、窗口和会议身份，通过公共辅助功能打开并确认退出，再读回会议窗口消失。切换会议、已有他人退出弹窗或无法确认身份时停止，不盲点、不重复确认。一对一会议若需要主持人交接，只在确认当前会议仍有且仅有另一位参会者时，选择该唯一接任者、读回选中状态，再执行一次“Assign and leave”。多人会议仍由本人选择接任者，不自动结束全场。失败会保留记录、停止代理并提示在 Zoom 中检查；不会把已派发的点击写成已退出。

开场问候等待回答时，“还行吧”“不忙”等完整简短寒暄直接接入唯一的已配置共享介绍，取消同轮模型自行生成的过渡语。包含实际问题、暂停或反问的发言仍保留正常问答；旧音频转写不会触发这项交接。

共享选择器同时兼容旧版三标签和 Zoom 7.2 的四标签（Screens、Windows、Files、Other）。按实际控件语义选择 Files，并读回选中状态；共享按钮返回错误时，也按相同规则验证界面是否已切换。只有目标文稿 ID 和真实放映页码确认后才开始讲述。
