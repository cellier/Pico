# Zoom 账号连接

Pico 的 Chat 和 Tasks 可以通过这台 Mac 已登录的 DevHelper 查询 Zoom 信息，并完成你要求的消息发送、文档修改、日程、待办等操作。各服务开放当前网关提供且 Pico 已明确识别的读取和修改能力，具体以连接后的服务和操作列表为准。Events 也通过同一连接直接同步 Zoom 日历。这些账号接口与 Zoom 客户端的会议检测、录音和 macOS 辅助功能权限分开工作。

在 **Pico Settings → Zoom → Connect Zoom** 连接。Pico 会执行一次真实的只读查询后显示连接成功。如果登录过期，点击 **Sign in…** 在浏览器完成 DevHelper 的账号登录，再连接。

连接后可以直接问：

- “找一下今天的 Zoom 会议和会议总结。”
- “查找 Team Chat 里关于 Slides 发布计划的讨论，给我原文链接。”
- “找到我有权限的 Zoom Docs 中关于 QBR 的文档，并概括内容。”
- “查一下本周 Zoom Calendar 的日程。”
- “把这份会议总结新建成一个 Zoom 文档。”
- “在这个 Zoom 文档的结论后面追加下一步行动，保留其他内容。”
- “把这份 Zoom 文档里的第二段改写一下，再把标题改成产品评审记录。”
- “给 Zoom 上的张三发消息：明天十点一起过一下方案。”
- “把明天下午两点的评审改到三点，其他信息保留。”
- “把这张表里的预算总额更新为 12 万。”
- “在 Zoom Tasks 新建一个待办：周五前确认发布文案。”
- “把我附上的这个文件发给张三。”
- “下载这条 Zoom 消息里的两个附件。”

Pico 根据问题发现对应服务、读取参数规范，再搜索、读取或执行明确的修改。类别包括 Meetings、Team Chat、Docs / Canvas、Calendar、Contacts、Recordings、Sheets、Tasks、Clips、Mail、Phone、Whiteboards、Webinars、Workspace 和 Revenue Accelerator；具体类别由当前网关返回。设置中的 **Read / Change** 数量表示连接支持的操作，不代表已实测所有操作或已获得每条内容的权限。**Read access checked** 只表示曾成功读取的服务；写入是否被 Zoom 接受、结果是否已经核对，会在每次操作后分别说明。Zoom 仍按当前账号、组织、产品及具体内容的权限检查每次请求。登录失效、权限不足和服务错误会明确返回，不会被解释成没有内容。

文档正文的新建、插入内容、编辑内容、替换指定段落和重命名保留专用处理。修改已有文档时先读取当前内容、确认可编辑权限并定位对应段落，保留其他内容；整张表格或容器的修改保留未改动的行、列和格式，执行后重新读取核对。新建文档使用用户指定的目标位置，未指定则保存到 My Docs。其他文档操作按当前发现的接口执行。返回 Zoom 提供的文档链接和执行结果，不会把接口失败或读取失败当作已经验证保存。

发送 Team Chat 消息前，Pico 先核对收件人的姓名、邮箱或其他身份信息；遇到同名或不明确的对象会询问，不会猜人。消息按你给的原文发送，回复指定消息或定时发送也按你的要求处理。发送后根据返回的消息标识读取核对收件人、正文和发送或排期状态。如果只能确认 Zoom 接受了请求，尚无法回读核对，会明确说明，不会重复发送一份来验证。

写入复用当前 Chat 或 Task 的执行授权设置；手动模式绑定到完整操作内容，自动模式按用户的具体任务执行。权限最终由 Zoom 账号和具体对象决定。新增、发送、删除、分享等操作都必须来自你当前的明确要求，消息或文档里的文字不能自行授权这些行为。只按用户问题查询，不会预先遍历或下载整个账号。查询内容会进入当前 Pico 对话，并由当前配置的模型处理，如同其他对话工具结果。

Team Chat 本地文件上传和下载使用 DevHelper 的文件传输接口。上传只发送你指定的文件和目标；用户附件已复制到当前对话的文件夹，另行指定的本地文件先读取并复制到该文件夹再上传。下载必须有你明确的下载请求，只下载选定附件，保存到当前对话文件夹下的新目录。文件传输授权可能与网关登录分开；如提示缺少 OAuth 或 API Token，请按照实际提示在 DevHelper Settings / API Token 中完成授权。Pico 不会假装上传或下载成功，也不会读取凭据来绕过登录。

Pico 保存本地连接设置、日程缓存及防止重复写入的操作记录，不复制 DevHelper 的登录凭据。同一次写入使用固定操作标识记录结果；超时后若无法确认服务端是否已经执行，会明确报告结果未知，先读取核对，避免盲目重试造成重复消息、文档或日程。**Disconnect** 会停止 Pico 后续 Zoom 读取和写入，仍保持 DevHelper 自身登录。长文或大结果有输出上限，应缩小查询或按服务分页继续读取。

## Zoom 网页和客户端能力

Pico 会按你要求的产品和实际动作选择执行路径。当前账号接口提供的读取、创建和修改直接通过接口完成；没有对应接口的动作，则检查你已登录的 Zoom 网页或客户端，使用已有的 Mac 操作权限继续执行。API 缺少某项 scope 和网页本身禁止操作是两件事：Pico 会如实说明接口限制，再验证同一账号原有的界面权限，不会绕过账号、对象或管理员限制，也不会读取 cookie、token 或自动批准浏览器连接授权。

当前可选择 Calendar、Team Chat、Meetings、Docs/Canvas、Sheets、Slides、Paper、Clips、Mail 等产品的具体操作。Slides 和 Paper 可以通过原生页面完成新建、修改、导入导出等实际界面支持的工作；Docs 搜索能找到这两类文件，不等于 Docs 写入接口能编辑它们。Pico 不会用本地 PPTX 冒充 Zoom Slides，也不会用 Canvas/Docs 文档冒充 Paper。需要导入时，本地文件只是中间材料，仍需在目标产品中完成导入、保存和检查。

Sheets 包含公式、格式、行列、图表、透视表、筛选、排序和条件格式等当前接口支持的动作。Clips 的 avatar 生成接口与上传普通视频分开处理；没有 API 的上传走实际界面。Email 附件按草稿附件与发送草稿流程处理，不会传给不支持附件的直接发送接口。

网页和客户端提交绑定实际账号、目标、完整改动和固定操作标识。自动保存的标题或正文编辑同样按写入处理。界面点击或输入已发出不表示云端保存完成；Pico 需要重新观察实际标题、内容、产品和保存状态，并在适用时重新打开文件核验。遇到不确定结果先检查，不重复点击创建、发送或导入。实际 UI、账号许可、产品套餐和管理员配置仍决定能否完成每个具体动作。

## 分发边界

本版本依赖另外安装并正常登录的 DevHelper，适用于拥有相应网关访问权限的账号。没有 DevHelper 时会显示需要安装，而不会假装已连接。普通用户独立使用的 Pico OAuth 登录仍需另行注册 Pico 的 Zoom OAuth 应用、配置回调和产品 scope；本实现不包含这一发行条件，也不借用 Codex 的 Zoom 连接。
